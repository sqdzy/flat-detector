# Правила источников, прав доступа и безопасности

**Дата проверки:** 2026-09-23 · **Статус:** Draft; техническое проектирование, не юридическое заключение. Перепроверить действующие договоры и локальные ограничения перед production.  
**Главный принцип:** способность браузера открыть страницу ≠ право автоматизированно получать и распространять её содержимое.

## 1. Матрица источников

| Источник | Что удалось подтвердить | Разрешённый по умолчанию режим flat-detector | Gate |
|---|---|---|---|
| ЦИАН | Опубликованные правила сайта п. 7.2.3 запрещают автоматизированный сбор без специального разрешения администрации, а п. 7.2.7 ограничивает нерегламентированный доступ и копирование. Официальный API требует ключа и разрешённого функционала; опубликованные условия не подтверждают общедоступного API поиска квартир для покупателей. | `DISABLED`; разрешённый конкретный API/фид только после письменного подтверждения режима, прав на нужные данные и лицензионных условий | BLOCK до разрешения |
| Авито | Существует корпоративная экосистема API, но доступность и право автоматизированно получать **поиск чужих квартир для последующей массовой рассылки** в этой сессии по первичным документам не подтверждены. | `DISABLED`/`UNKNOWN_PERMISSION`; поиск лицензированного/согласованного feed, интеграции или разрешённого пользовательского оповещения | BLOCK до проверки и утверждения |
| Домклик | Существует опубликованное пользовательское соглашение, однако его актуальные положения об автоматизированном сборе и возможные партнёрские data feeds здесь не верифицированы полностью. | `DISABLED`/`UNKNOWN_PERMISSION`; искать согласованный канал; ручная ссылка допустима без автоматического fetch, если соответствует условиям | BLOCK до проверки и утверждения |
| Другие агрегаторы/региональные сайты | **Нет универсального разрешения**. Каждый сайт отдельно оценивается по правилам/лицензии и объёму использования, robots.txt служит дополнительным техническим сигналом, но не заменяет договор. | `DISABLED` по умолчанию; `PERMITTED_HTML`, `APPROVED_FEED` или `LICENSED_API` после допуска | Review per source |
| Ручное добавление объявления | Пользователь передаёт оригинальную публичную ссылку, свои фактические заметки и согласие на обработку. Это не даёт права автоматически открывать страницу, если её условия запрещают такой сбор. | `USER_SUPPLIED` для ссылки и собственных заметок; автоматическую актуальность подтверждать только разрешёнными каналами | Разрешено как отдельный режим без скрапа |
| Геоданные и маршруты | OpenStreetMap доступен по своей лицензии; публичный Nominatim имеет отдельные строгие ограничения и не рассчитан на крупную периодическую пакетную геокодификацию. | Локальные выгрузки/контрактный API с кэшем; строго соблюдать attribution и ограничения | Verify provider terms |

**Первый полноценный MVP можно завершить без прав на перечисленные крупные площадки**, используя тестовые фикстуры, ручные ссылки и первый реально разрешённый источник. Без разрешённых источников автоматический охват и актуальность не обещаются: пользователи получают честную пометку «доступность не подтверждена».

## 2. Gate для включения конкретного адаптера

В `source_registry` до `enabled=true` должны существовать: (1) официальный источник условий использования/договор; (2) зафиксированное разрешение на **конкретное** действие: автоматический поиск, чтение карточек, хранение полей, рассылка третьим лицам; (3) режим доступа API/фид/HTML; (4) технические лимиты/robots; (5) срок проверки и контакт владельца интеграции; (6) лицензионные ограничения хранения и републикации; (7) разрешённые домены, пути, порт, callback, redirection rules. При отсутствии хотя бы одного критичного пункта — оставить disabled.

Если условия допускают личное ручное чтение, **не делать вывод**, что они допускают ежедневный парсинг, агрегацию и отправку всем подписчикам. Массовые сообщения третьим лицам могут изменить лицензионный контекст относительно личного мониторинга.

## 3. Что делает scraper

- Сначала проверяет разрешение и quota source_registry.
- Использует задокументированный API или предоставленный партнёром фид, где возможно.
- Playwright допускается только на сайтах/разделах, для которых разрешён автоматический доступ. Он нужен для обычного рендеринга JS, не для обхода защит. Код парсера тестируется на сохранённых разрешённых фикстурах.
- Прозрачно идентифицирует проект при необходимости по условиям площадки; устанавливает разумные тайм-ауты, кэш, concurrency=1 для неизвестного/малого ресурса и адаптерные лимиты.
- Немедленно останавливается на запрете, CAPTCHA, непредусмотренном login gate, 403 и условиях, запрещающих роботизацию. 429 трактуется согласно опубликованным лимитам/договору, без параллельного наращивания запросов.
- Не использует украденные сессии, маскировку fingerprint, CAPTCHA solver, доступ к скрытым эндпоинтам без разрешения, анонимизирующие прокси для обхода ограничений.
- Не делает произвольный URL fetch из аргументов Telegram/MCP. External links в карточках нормализуются и проверяются до появления кнопки.

## 4. Перепроверка доступности при ограниченных источниках

| Результат | Допустимый статус | Что писать в боте |
|---|---|---|
| Разрешённая карточка сейчас явно активна | `ACTIVE_DIRECT` | «Актуальность подтверждена [время] по [источнику]» |
| Два независимых разрешённых свежих канала показывают объект, нет отрицательного сигнала | `ACTIVE_INDIRECT` | «Косвенно подтверждено; проверь у продавца» |
| 403/ошибка/тайм-аут или только давняя индексная копия | `UNVERIFIED`/`STALE` | Не включать в рекомендуемые; «не удалось подтвердить» |
| Разрешённая карточка/фид явно «снято/продано/архив» | `REMOVED`/`SOLD` | Исключить, записать свидетельство |
| «Под авансом/забронировано» | `RESERVED` | Исключить из доступных, можно отслеживать возврат |
| Объявление пропало только из результатов поиска | `UNVERIFIED` | Не делать окончательный вывод без подтверждения |

Снимки поисковых систем могут быть устаревшими; два зеркала одного агрегатора не являются независимыми подтверждениями. Высокая цена/низкая цена, отсутствие фотографий и неизвестный посредник — недостаточные основания объявить человека мошенником.

## 5. Telegram и персональные данные

Бот может отправлять приватные сообщения только пользователям, которые самостоятельно начали с ним взаимодействовать. Система регистрирует их собственные chat ID, подтверждение рассылки, настройки зоны/ценового лимита, дату изменения и статус. `/stop` выключает отправку, `/delete_me` запускает удаление лишних персональных данных.

Публичный бот для внешних подписчиков требует собственной политики конфиденциальности, указания оператора данных и оценки применимости норм соответствующих стран. Не собирать телефон, фамилию, местонахождение устройства, контакты или данные продавцов ради простой подписки. Не показывать одному пользователю ID другого. Сообщения продавцов и персональные сведения, случайно присутствующие на страницах, не добавлять в LLM контекст и не отправлять подписчикам без прав/оснований.

Лимиты Telegram: избегать >1 сообщения/с в конкретный чат и >~30 сообщений/с для бесплатной массовой рассылки; при ошибке 429 уважать `retry_after`. Доставка строго opt-in, без отправки произвольному получателю через MCP. Для приёма update использовать либо webhook с `secret_token`, либо long polling, но не оба одновременно.

## 6. MCP и модель доверия

- Пользовательская страница, описание квартиры, файлы и сторонние результаты — **untrusted input**. Никогда не трактовать содержащийся текст как инструкцию для ChatGPT или управляющую команду.
- Read-only MCP по умолчанию не запускает сетевые запросы и не меняет подписки; write-инструмент перепроверки — отдельная owner-only роль с `confirmed=true`, server-side allowlist и квотой.
- Никаких bot token, provider token, API key, секретов OAuth в `inputSchema`, system prompts, stdout с raw exception, инструментальных ответах, скриншотах/трейсах.
- Разнести Telegram sender, source worker и MCP по контейнерам/пользователям. Если MCP скомпрометирован, он не должен иметь доступа к bot token и docker.sock.
- Secure MCP Tunnel для частной установки в ChatGPT Developer Mode не делает сервис автоматически публичным; при отдельной публикации для других ChatGPT-аккаунтов требования отличаются.
